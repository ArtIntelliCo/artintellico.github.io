# Модернизация сайта artintellico.com

Дата: 2026-08-10
Статус: согласовано с заказчиком, готово к планированию реализации

## Задача

Перевести сайт-визитку artintellico.com с мёртвого стека 2019 года (Middleman 4.3.5 + Ruby 2.6) на современный статический генератор, починить многоязычность и базовое SEO, освежить оформление без смены визуальной идентичности.

## Что не так сейчас

Аудит текущего состояния, проведённый перед проектированием:

1. **Многоязычность существует только формально.** Полноценная страница есть только на русском (`source/index.html.erb`). Файлы `source/localizable/index.uk.html.erb` и `index.en.html.erb` — невычищенные демо-заглушки шаблона ThemeFisher: заголовок `Welcome to ArtIntelliCo`, разделы «Our Services / Smooth Touch», под украинским `<h1>` идёт английский текст, `image_tag 'watch.png'` ссылается на несуществующий файл. В `source/layouts/layout.erb` жёстко зашит `<html lang="ru">`, поэтому en- и uk-страницы объявляют себя русскими. Переключателя языков нет, `hreflang` нет.
2. **Стек не собирается на современном окружении.** Middleman 4.3.5 требует Ruby 2.6 (EOL с 2022) и `activesupport 5.0.7.2`; на Ruby 3.3 проект не запускается. Локальный запуск потребовал Docker-контейнера `ruby:2.6` с доустановкой Node.js для ExecJS.
3. **Мёртвый вес.** В репозитории три копии Bootstrap (локальные 3 и 4 плюс подключённый с CDN 4.1.3), jQuery 2.1.1 и восемь плагинов (`wow`, `sticky`, `nav`, `magnific-popup`, `countdown`, `validate`, `form`), шрифт иконок ThemeFisher на 1 МБ, `animate.css`. На странице нет ни формы, ни попапа, ни счётчика — ничто из этого не используется.
4. **Контент устарел и содержит ошибки.** На главной с 2019 года висит блок «Наш сайт находится на реконструкции», в подвале зафиксирован `Copyright © 2019`. Опечатки в живом тексте: `поддрежка` в `<title>`, `AtrIntelliCo` в подвале, `Искуственным`, `бранирования`. Ссылка `mailto:io@artintelico.com` содержит битый домен (пропущена вторая `l`) — письма с сайта уходят в никуда.
5. **SEO-база отсутствует.** `robots.txt` и `sitemap.xml` на проде отдают 404. Нет canonical, Open Graph, Twitter Card, структурированных данных.
6. **Деплой ручной.** `middleman-deploy` запускается с локальной машины; собрать сайт может только тот, у кого настроено окружение Ruby 2.6. CI отсутствует.

## Решения, принятые заказчиком

| Вопрос | Решение |
|---|---|
| Тип сайта | Одностраничная визитка, структура как сейчас |
| Движок | Astro (актуальная стабильная версия, на дату спецификации — 7.2.0) |
| Источник текстов | Перевод текущего русского текста на uk и en, вычитка на стороне заказчика |
| URL-схема | Корень — украинский, `/ru/`, `/en/`; `/uk/` редиректит на корень |
| Хостинг | Остаётся GitHub Pages, деплой через GitHub Actions |
| Обратная связь | Без формы: телефон, email, мессенджеры |
| Оформление | Освежить в том же духе, фирменный SVG-логотип и его палитра сохраняются |

## Архитектура

### Репозиторий

Остаётся один репозиторий `ArtIntelliCo/artintellico.github.io`. Ветка `development` становится основной и содержит Astro-проект. В настройках Pages источник переключается с ветки на GitHub Actions, после чего ветка `master` (собранная статика Middleman) перестаёт использоваться. Её содержимое фиксируется тегом `legacy-middleman-build` и не удаляется. Исходники Middleman остаются доступны в истории git.

### Структура проекта

```
astro.config.mjs
package.json
.github/workflows/deploy.yml
public/
  CNAME                    # artintellico.com
  robots.txt
  favicon.ico + apple-touch-icon-*.png   # переносятся как есть
  og-image.png             # новое, для превью в мессенджерах
src/
  layouts/
    Base.astro             # <html lang>, мета, canonical, hreflang, JSON-LD, GTM
  components/
    Header.astro
    LangSwitcher.astro
    Hero.astro             # inline-SVG логотипа
    Services.astro
    Contacts.astro
    Footer.astro
  pages/
    index.astro            # /      → uk
    ru/index.astro         # /ru/
    en/index.astro         # /en/
  i18n/
    uk.json
    ru.json
    en.json
    index.ts               # загрузка словаря по локали, типизация ключей
  data/
    services.ts            # список услуг: ключ + порядок, тексты в словарях
```

Разметка страницы существует в одном экземпляре: три файла в `pages/` — тонкие обёртки, каждая передаёт свою локаль в общие компоненты. Тексты приходят из словаря. Это устраняет корневую причину нынешнего расхождения версий: забыть перевести блок физически нельзя, отсутствующий ключ обнаруживается сразу.

### Компонентные границы

- `Base.astro` — единственное место, где формируются `<head>`, `hreflang`, canonical, JSON-LD и подключается GTM. Принимает `lang` и данные страницы, ничего не знает о содержимом секций.
- `LangSwitcher.astro` — принимает текущую локаль, отдаёт три ссылки на соответствующие URL. Единственное место, где живёт знание о соответствии «локаль → путь».
- Секционные компоненты (`Hero`, `Services`, `Contacts`) принимают уже готовые строки из словаря и не обращаются к i18n-слою напрямую.
- `services.ts` держит только структуру (ключи и порядок), тексты — в словарях.

## Многоязычность

### Конфигурация

```js
// astro.config.mjs
i18n: {
  locales: ['uk', 'ru', 'en'],
  defaultLocale: 'uk',
  routing: {
    prefixDefaultLocale: false,
    redirectToDefaultLocale: false,
  },
}
```

`prefixDefaultLocale: false` даёт украинскую версию в корне без префикса. `/uk/` при такой схеме не генерируется, поэтому старый адрес закрывается явным редиректом через `redirects` в конфиге. При статической сборке Astro создаёт страницу с `<meta http-equiv="refresh">` и canonical на целевой URL. Настоящий 301 на GitHub Pages недоступен; для одного legacy-адреса meta-refresh достаточен.

### Итоговая карта URL

| URL | Содержимое |
|---|---|
| `/` | украинская версия, `hreflang="x-default"` и `hreflang="uk"` |
| `/ru/` | русская версия |
| `/en/` | английская версия |
| `/uk/` | meta-refresh на `/` |

### Разметка для поисковиков

На каждой странице:
- `<html lang="uk|ru|en">` — подставляется из локали, а не зашивается;
- `<link rel="canonical">` на собственный URL;
- полный набор `<link rel="alternate" hreflang>` для `uk`, `ru`, `en` и `x-default` на корень.

### Переключатель языков

В шапке — `UK · RU · EN`, текущий язык выделен и некликабелен, у контейнера `aria-label`. Переключатель ведёт на ту же страницу в другом языке (для одностраничного сайта это всегда корень соответствующей локали). Автоопределение языка по браузеру не делается: на статике оно возможно только через JS-редирект, который ломает индексацию и раздражает пользователей, осознанно выбравших язык.

### Последствие смены языка в корне

Сейчас в корне русская версия, после переезда там будет украинская. Внешние ссылки на `artintellico.com` начнут открывать украинский текст, Google переиндексирует главную как украинскую. Учитывая, что сейчас на главной висит заглушка «сайт на реконструкции» и органического трафика по сути нет, риск принят заказчиком осознанно.

## Контент

Русская версия — источник. Порядок работы: правка русского → перевод на украинский → перевод на английский.

Правки, которые вносятся в исходный русский текст:
- `поддрежка` → `поддержка` (тег `<title>`);
- `AtrIntelliCo` → `ArtIntelliCo` (подвал);
- `Искуственным` → `Искусственным`;
- `бранирования` → `бронирования`;
- `mailto:io@artintelico.com` → `mailto:io@artintellico.com`;
- `Copyright © 2019` → год вычисляется при сборке.

Блок «Наш сайт находится на реконструкции» удаляется. На его месте — контактная секция с email `io@artintellico.com`. Телефон на сайте не публикуется (решение заказчика от 10.08.2026): его нет ни в разметке, ни в структурированных данных, ни в текстах. Кнопки мессенджеров добавляются только если заказчик передаст ссылки; в базовом объёме их нет.

Девять услуг сохраняются и раскладываются сеткой карточек вместо сплошного текста в три колонки.

Украинская версия вычитывается заказчиком в первую очередь как основная.

## Оформление

Tailwind. Палитра берётся из фирменного SVG-логотипа:

| Роль | Цвет |
|---|---|
| Тёмно-синий (текст, тёмные секции) | `#1D2A46` |
| Синий (акцент, ссылки) | `#20769F` |
| Охра | `#E7B744` |
| Терракота | `#DF542F` / `#E87F34` |

Логотип остаётся inline-SVG без изменений.

Удаляются: jQuery и все восемь плагинов, три копии Bootstrap, шрифт иконок ThemeFisher (1 МБ), `animate.css`, `magnific-popup`, `modernizr`, `tether`.

Шрифты перестают загружаться со стороннего CDN: используется системный стек шрифтов. Это даёт ноль сетевых запросов на типографику и корректную кириллицу на всех платформах. Если заказчик позже захочет фирменное семейство, оно кладётся в `public/fonts` и подключается локально — на архитектуру это не влияет. На выходе страница не имеет внешних блокирующих зависимостей, кроме GTM.

Доступность: осмысленные `alt`, видимый `:focus-visible`, проверенный контраст текста на тёмных секциях, уважение `prefers-reduced-motion`.

## SEO и аналитика

- `public/robots.txt` со ссылкой на sitemap;
- `sitemap.xml` через `@astrojs/sitemap` с i18n-разметкой всех трёх локалей;
- canonical и `hreflang` (см. раздел о многоязычности);
- Open Graph и Twitter Card с `og:image`, `og:locale` и `og:locale:alternate`;
- JSON-LD `Organization`: название, URL, логотип, телефон, email;
- контейнер GTM `GTM-W3Z644V` переносится без изменений, включая `<noscript>`-фолбэк.

## Сборка и деплой

GitHub Actions по пушу в основную ветку и по `workflow_dispatch`:

- `actions/checkout@v7`
- `withastro/action@v6` (сборка)
- `actions/deploy-pages@v5` (публикация)

Права job: `contents: read`, `pages: write`, `id-token: write`. В `astro.config.mjs` задаётся `site: 'https://artintellico.com'`.

Локальная разработка: `npm install && npm run dev`. Ruby, Docker и ручной `middleman deploy` уходят из процесса полностью.

## Проверка результата

- Сборка проходит и генерирует ровно четыре HTML: `/`, `/ru/`, `/en/`, `/uk/` (редирект).
- Каждая страница отдаёт корректный `lang`, canonical на себя и три `hreflang` + `x-default`.
- Ни один ключ словаря не остался непереведённым: украинский словарь задаёт тип, русский и английский типизируются по нему, и `astro check` падает при отсутствующем ключе.
- `robots.txt` и `sitemap.xml` доступны и содержат все три локали.
- В собранном HTML нет ссылок на jQuery, Bootstrap, ThemeFisher и Google Fonts CDN.
- Страница корректна на мобильном разрешении, переключатель языков работает во всех трёх версиях.
- Ссылки `tel:` и `mailto:` ведут на верные адреса.

## Вне объёма

Сознательно не входит в эту работу:

- форма заявки и любой бэкенд под неё;
- блог, кейсы, портфолио, отдельные страницы услуг;
- редизайн с нуля;
- перенос домена на другой хостинг (Cloudflare Pages и аналоги);
- смена аналитики;
- пересмотр позиционирования и маркетинговых текстов сверх исправления ошибок и перевода.
